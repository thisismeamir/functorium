# Hybrid Methods

If an intermediate language is employed, it's possible to combine compilation and interpretation. The compiler translates from the high-level language to this intermediate language, which is then interpreted on the machine executing the program. An interpreter written in a high-level language can be compiled on different platforms, facilitating portability; it only requires that the language used for the interpreter itself is already implemented on the new platform. C is commonly chosen for writing such interpreters due to its widespread availability and sufficient low-level control for performance.

Combining interpretation and compilation during execution offers advantages: Interpretation performs better with little or no repetition, while compilation excels when there's significant repetition (e.g., loops or repeated function calls). Some virtual machines employ a strategy of initial interpretation followed by just-in-time (JIT) compilation after a code segment has been executed a certain number of times. This leverages the benefits of both approaches, expecting that frequently executed code is likely to be re-executed.

This hybrid approach, used in several JVM implementations, is more complex than pure compilation or interpretation but can yield better overall performance, particularly for large programs with varying execution frequencies. The strategy can be generalized to multiple levels: initial interpretation, followed by simple compilation, and then optimized compilation (triggered by frequent execution).  The interpreter or the initially compiled code can collect profiling information used to guide optimization in later stages.
